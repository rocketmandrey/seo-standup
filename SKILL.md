# SEO Standup — проектирование сайта под существующий спрос

## Идея

SEO — это не магия про ключевые слова и не производство тысяч текстов.
Это инженерная работа: найти существующий спрос → понять намерение
человека → спроектировать под спрос структуру сайта → создать лучший
возможный ответ → улучшать его по реальным данным.

Три метафоры, на которых держится весь пайплайн:

1. **Рынок.** Поисковик — продавец, к которому каждый день приходят люди
   и говорят, чего хотят. Не гадай, что вырастить, — сначала спроси рынок.
2. **Сеть.** Каждый запрос — рыба, структура сайта — сеть. Задача — не
   «написать много статей», а спроектировать сеть, которая закрывает
   нужное море спроса без дыр и без двух ячеек на одну рыбу.
3. **Цикл.** Спрос → страница → реальные показы → новые запросы →
   улучшение → повтор. SEO не заканчивается публикацией — там оно
   начинается.

## When to Use

- «Какой спрос есть вокруг X и что под него строить?»
- «Спроектируй структуру сайта / посадочные под нишу».
- «Сделай ТЗ на статью, которая обгонит выдачу».
- «Что улучшить на странице по данным Search Console?»

Не используй для накрутки, дорвеев, массового скрейпинга выдачи и
обхода ограничений поисковиков.

## Принцип zero-credit

Скилл полностью рабочий **без единого API-ключа и без трат**:
бесплатные источники (Wordstat вручную, поисковые подсказки, сама
выдача, Search Console владельца сайта) закрывают каждый этап.

Платные источники — только опциональные усилители, и только если у
пользователя уже есть свои ключи:

- **Topvisor** — частотность и расширение семантики пакетно;
- **XMLRiver** — SERP-снимки без ручного просмотра;
- **Semrush** — кросс-чек по Google.

Правила для платного слоя: ключи только из окружения или локального
secret storage, никогда не печатать и не коммитить; перед каждым
расходным вызовом — scope, цена и отдельное явное подтверждение
пользователя. Нет ключа — не блокер: работай бесплатным путём.

## Workflow

### 1. Собрать спрос

Нормализуй seed: варианты написания, транслитерация, вопросные и
коммерческие модификаторы. Раздели бренд и generic. Затем собери
реальные запросы:

- бесплатно: Wordstat (глазами), подсказки Яндекса/Google по seed
  и модификаторам, блоки «Люди также спрашивают» / related searches;
- с ключами: Topvisor — частотность с датой среза, match type отдельно
  (broad / phrase / exact, не смешивая), связанные запросы, сезонность.

Частотность — это оценка спроса (показы), а не трафик. Фиксируй дату,
регион, поисковик у каждой цифры.

**Done when:** есть таблица запросов с источником и датой среза.

### 2. Кластеризовать по интенту

Дедуплицируй и разложи запросы по намерению пользователя — это работа
для LLM: дай модели список запросов и попроси сгруппировать по интенту
(brand / commercial / informational / navigational / local).

«Купить яблоки», «купить красные яблоки», «красные яблоки цена» — один
кластер: человек хочет купить. «Когда собирать яблоки» — другой.

Оценивай кластеры по спросу, деловому интенту и релевантности продукту —
раздельными факторами, без одного «общего балла».

**Done when:** shortlist кластеров с прозрачными причинами выбора.

### 3. Спроектировать сеть

Прежде чем производить контент — спроектируй структуру. Каждой странице
назначь конкретный кластер и тип: коммерческая, каталог, калькулятор,
статья, сравнение. Проверь два антипаттерна:

- **дыра** — кластер со спросом, под который нет страницы (рыба
  проплывает мимо);
- **каннибализация** — две страницы под один кластер (конкурируют
  друг с другом).

**Done when:** карта «страница → кластер → тип → priority», где у каждой
страницы одно предназначение и ни один значимый кластер не остался
без ячейки.

### 4. Контент по ТЗ из выдачи

Худший вариант — «напиши хорошую SEO-статью про X»: модель напишет
среднее из головы. Вместо этого:

1. Открой выдачу по целевому запросу (глазами; с ключами — XMLRiver).
2. Разбери топ: что отвечают, какие вопросы закрывают, какая структура,
   какие таблицы / картинки / калькуляторы.
3. Собери из этого ТЗ: обязательные блоки, вопросы, форматы.
4. Попроси модель сделать материал, который закрывает потребность
   полнее и удобнее топа — не копию конкурентов, а лучший ответ.

**Done when:** ТЗ ссылается на конкретные страницы выдачи; черновик
закрывает каждый пункт ТЗ.

### 5. Замкнуть цикл

После индексации Search Console показывает, по каким **реальным**
запросам поисковик показывает страницу — и они не всегда совпадают
с плановыми. Дальше цикл:

1. Выгрузи реальные запросы страницы из Search Console.
2. Спроси модель: «Вот запросы, с которыми приходят люди. Страница
   идеально на них отвечает?»
3. Внеси правки: недостающие ответы, порядок блоков, лишнее — убрать.
4. Подожди новые данные. Повтори.

**Done when:** у каждой приоритетной страницы есть дата последней
итерации цикла и список закрытых из Search Console запросов.

## Output Template

```markdown
# Ниша: <seed>
Срез: <дата>; рынок: <поисковик, регион>

## Спрос
| Кластер | Примеры запросов | Интент | Частотность | Источник/дата |

## Сеть
| Страница | Тип | Кластер | Статус | Priority |

## ТЗ / контент
| Страница | Референсы из выдачи | Обязательные блоки | Статус |

## Цикл
| Страница | Реальные запросы (GSC) | Правки | Дата итерации |
```

## Common Pitfalls

1. **Путать спрос с трафиком.** Частотность — прогноз показов, не визиты.
2. **Смешивать регионы и match types.** Каждая строка хранит их отдельно.
3. **Писать контент до проектирования сети.** Сначала карта, потом текст.
4. **Просить «хорошую SEO-статью» без ТЗ из выдачи.** Получишь среднее.
5. **Считать публикацию финишем.** Без цикла по Search Console страница
   застывает на первой версии.
6. **Тратить кредиты «на всякий случай».** Платный вызов — только после
   scope + цена + явное «да».

## Verification Checklist

- [ ] У каждой цифры спроса есть источник, дата, регион, match type.
- [ ] Кластеры разложены по интенту, без «общего балла».
- [ ] В карте сайта нет дыр и каннибализации.
- [ ] Каждое ТЗ опирается на разбор реальной выдачи.
- [ ] Для живых страниц цикл Search Console запущен и датирован.
- [ ] Платные вызовы (если были) согласованы отдельно; секретов в
      отчётах и коммитах нет.
